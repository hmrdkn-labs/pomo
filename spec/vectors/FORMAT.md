# Test vector format

One JSON file per scenario in this directory, named `NNN-slug.json`. Every Core build must pass all of them.

```json
{
  "name": "pause-resume-complete",
  "description": "one line",
  "config": { "long_break_every": 4 },
  "events": [
    { "id": "00000000-0000-4000-8000-000000000001", "device_id": "mac", "seq": 1,
      "hlc_ms": 1000000, "hlc_counter": 0, "type": "timer.started",
      "payload": { "block_id": "b1", "kind": "focus", "planned_ms": 1500000, "label": "spec" },
      "source": "user", "command_key": null }
  ],
  "order_independent": true,
  "checks": [
    {
      "now_ms": 1200000,
      "timer": { "status": "running", "block_id": "b1", "remaining_ms": 1300000, "next_kind": "focus" },
      "blocks": [
        { "id": "b1", "kind": "focus", "label": "spec", "project": null, "outcome": null,
          "elapsed_ms": null, "phase": "running" }
      ],
      "stats": { "tz_offset_min": 0, "focus_ms_by_day": { "1970-01-01": 0 }, "completed_focus": 0 }
    }
  ]
}
```

Rules:

- `events` is the full set, listed in any order. The runner sorts nothing itself: it ingests them in the listed order into a fresh store, and the Core must produce the specified state. If `order_independent` is true the runner also ingests them in reverse order and in the order of a fixed shuffle, and in each case with every event ingested twice; results must be identical.
- Each entry of `checks` is evaluated independently at its `now_ms`, against the full event set.
- In `timer`: `status` is `idle`, `running` or `paused`. `block_id` and `remaining_ms` are present only when status is not `idle`. `next_kind` is the suggested next kind (see `../events.md`, Cycle).
- In `blocks`: every block that exists must be listed, ordered by `started_ms` then `id`. A field set to `null` in `expect` means "must be null" for `label`, `project`, `outcome`; for `elapsed_ms` a `null` means "do not check" (used for live blocks, where `timer.remaining_ms` is the checked number).
- `stats` is optional. `focus_ms_by_day` lists every day with focus blocks, keys `YYYY-MM-DD` in the given fixed offset; `streak_days` may be added. `completed_focus` is a count.
- Idempotency scenarios use a separate shape, `"commands"`, listed in a file named `NNN-cmd-slug.json`:

```json
{
  "name": "start-is-idempotent",
  "device_id": "mac",
  "steps": [
    { "now_ms": 1000, "command": { "type": "start", "kind": "focus", "planned_ms": 60000, "command_key": "k1" }, "expect": "ok" },
    { "now_ms": 2000, "command": { "type": "start", "kind": "focus", "planned_ms": 60000, "command_key": "k1" }, "expect": "ok", "same_events_as_step": 0 },
    { "now_ms": 3000, "command": { "type": "pause", "command_key": "k2" }, "expect": "ok" },
    { "now_ms": 4000, "command": { "type": "pause", "command_key": "k3" }, "expect": "error" }
  ],
  "final_event_count": 2
}
```

`expect` is `ok` or `error`. `same_events_as_step` says the returned events equal those of an earlier step. `final_event_count` is the log size at the end. Block ids in commands that create blocks are generated by the Core, so command vectors never assert them.
